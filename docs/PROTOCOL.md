## 2026-10-18客户风险最后复核

用户在上一批停止后追加授权最后优化与团队讲解文档。本轮独立登记`development_customer_risk_review_v1`，固定原A与同训练集最小方差的五个混合比例，在已有两套划分内用完整内层执行选择，外层不可调参。客户风险目标为P90不超过容忍度80%且较原A下降3个百分点，正常/双费用越界诊断上界≤20%，高流动性bills目标≥40%；这是新的客户风险优先选择标准，不放宽或替代原金融晋级。

选择家族500=5客户×5比例×2费用×2划分×5外折；同一选定配置的提前复核只作诊断，不另选赢家。全部比例失败时保存最小违约反事实路径并标记，不删折、不冒充合格自动推荐。实验完成即停止，不追加参数。

本批发生在原最终暴露之后，只处理开发分区，不构成独立确认；原金融核心、冻结映射、最终锁及两版ZIP保持hash。本轮未通过原金融晋级，最终金融程序仍为冻结A。团队讲解从保存结果生成，允许解释旧最终证据，不对新规则运行旧最终集。

## 开发程序

1. 情景 1–120 是唯一开发总体。运行前在 `configs/benchmark.json` 固定种子、候选、搜索预算、期限和成本。每次使用新目录，保留配置、环境、代码/分区 hash、训练参数、划分和调参记录。
2. 外层 5 折随机整情景划分，每折验证 24 条、训练 96 条。每个外层训练集再做 3 折整情景 CV，对四类门控策略分别在四组 `(gamma,buffer)` 中选择。共 4×4×3×5=240 次内层候选/折评价；未来扩展还应记录失败候选。
3. 均值、协方差、最优权重、归一化、早停和特征选择均只能使用该层训练 IDs。不能把外层验证情景用于任何选择；评价入口拒绝训练/评价 ID 重叠。
4. 内层在 H=30、官方费用下使用 `real_CAGR−0.10×real_MDD`。这是研究偏好，**不是官方评分**；系数表达不同量纲/时间解释下的取舍，不是普适换算率。费用已经包含在财富中。
5. 每个策略族选择与最优均值相差不超过一个配对标准误的候选，优先较大 buffer，再较大 gamma。这是稳定性启发式，不是统计检验；保存全部候选及选择结果。
6. 用外层训练数据重拟合，在未参与该折调参的情景上评价 H=5、6、15、25、30。原17策略不依赖期限，可截取同一完整路径；计划A及未来期限相关策略**必须逐期限重新实例化和模拟**。
7. 在 H=30 追加 0、0.125%、0.5%、1% 费用率。拟合参数不重调，但策略可根据新的成本作出不同决定。这是策略响应敏感性，不是按每种成本重新挑选赢家。

固定配置参照无训练参数，其 OOF 结果等同直接开发评价。学习策略的 OOF 结果评价的是“在 96 条情景上拟合/选择的程序”，不是最终在 120 条上拟合的单个模型。全开发集重拟合结果不能冒充独立评价。

## 计划A的额外选择与风险路线

`development_plan_a_v1`增加三产品和五个严格同锚对照，完整共25策略。每个内层训练模型解5期限×3产品×2风险比例=30个连续战略配置；每产品选择风险比例0.9/1.0、gamma4/12的四组合。每个组合在五个实际期限评价，不能用30年前缀替代。

选择仅使用内层折外结果，对每个H同时要求：实际路径对数回撤ES≤相应训练预算的平均值+0.005；相对同锚含费年度参照的中位增长损失≤0.001、P10增长损失≤0.002；复核率≤10%。各训练模型预算不同，此平均预算只是开发筛选口径，不构成条件风险保证。合格者选跨情景和期限平均`log(1+CAGR)`最高的组合；没有合格者时选标准化违约最小者并保存`selection_feasible=false`，不得称为风险约束通过。所有失败候选均保留调参记录。

原增长筛选继续执行。预声明风险路线相对原Balanced年度与同锚`plan_a_annual`分别检查：P90回撤降低至少3个百分点且多候选区间上界<0；中位增长区间下界≥−0.5个百分点/年；P10增长区间下界≥−0.2个百分点/年；至少4/5折风险下降；费用翻倍后风险仍下降且增长损失≤0.5个百分点；复核率≤10%。结果写入`risk_promotion_screen.csv`，是研究筛选而非官方评分或自动采用决定。

运行后不依据外层结果扩展参数。独立核验包括完整账本、所有年度收益重放、150个外层战略配置的区间穷举与LP证书、原17策略全部18,360行金融指标一致性。当前`generate_report=false`，只产出机器可读证据；不运行真实最终评价。

## 计划A第二轮：训练安全余量校准

`development_plan_a_calibrated_v1`保持25策略、原划分、收益门槛、复核规则和全部晋级阈值。每个产品/期限的验证目标固定为该训练样本上原产品配置的无费路径对数回撤CVaR90，即比例1.0；各候选训练预算取同一参照的0.75/0.85/0.95，分别留25%/15%/5%余量。三个比例×gamma4/12，共六组合，且均在看本轮外层指标前登记。

固定验证目标使安全余量可独立选择。它与第一轮比例0.9候选原有的较严验收线不同，因此“更多候选通过”不能单独视为风险改善；必须比较实际增长、回撤、费用与同锚对照。验证目标仍是样本估计，不是未来损失保证。

过紧预算可能无解，特别是保守产品的风险下限；记录LP松弛不可行证据，完整排除该组合并保存失败内层折。只在全部内层训练和该外层训练总体的重拟合均可行的候选中排名；该过滤只使用训练总体。完整执行风险、收益损失和复核率检查保持第一轮口径，风险线换为固定验证目标。没有通过者仍明确标记，不会放宽线或删除路径。

保存每候选五个期限的约束分解；独立核验训练可行/不可行证书、固定验证线和旧17策略一致性。固定选定模型后复算内层选择与联合年度顺序压力，不据压力结果更换模型。完成这批后停止扩展候选，继续封存真实最终情景121–180。

## 统计解释与重复试验

配对 bootstrap 重抽样的是**完整情景 ID**，保留策略/参照对应和路径指标。95% 百分位区间针对边际中位数或尾部分位数之差，不是逐情景差的中位数。胜率为配对场景中严格优于参照的比例，平局不计胜。

`family_lower/upper` 在单个“指标×期限×成本”内，对多候选使用 Bonferroni 尾概率；不覆盖全部图表、端点、期限、成本及研究迭代。4,000次bootstrap、原16个比较时极端端点只依赖约6次抽样，计划A的24个比较约4次，较粗糙。把它作为保守探索筛选，不能声称精确覆盖保证。

OOF 训练折重叠；当前 bootstrap 不重新拟合，因此遗漏训练不确定性，也不能消除共享训练样本的依赖。固定策略没有这一训练重叠问题。n=120 的 P90 尾部只有约 12 条路径，n=60 只有约 6 条。

Pareto 同时考虑中位 CAGR、P10 CAGR 越高越好，P90 MDD、实际费用越低越好。它是点估计的描述性支配关系，不含不确定性，不能单凭微小 Pareto 优势采用模型。独立性依据来自题目，而不是对生成器的统计证明。

持续查看外层 CV 仍会过拟合有限开发样本。用 `benchmark/experiment_registry.json` 记录日期、搜索预算、所有尝试与事后修改，限制候选数量。换随机种子只是一项稳定性研究，不是新的独立证据。嵌套 CV 约束预声明的内层搜索，不能消除无限次人工改模型的偏差。

## 新模型的比较与晋级

运行 MoE、MPC、RL 或稳健优化前，声明目标和可比较的简单参照。至少保留官方等权、同初始 Balanced 年度/持有参照和最相关的门控基准。比较期限、成本、训练数据、动作时点和可用信息必须一致。若声称时机选择改进，应匹配初始配置与可行敞口；不同风险约束下的成长/均衡组合差异不能全部归因于架构。

以下情况直接拒绝：信息泄漏、非法权重或核算、缺乏交易收益估计、隐藏求解失败、删除失败情景、无法解释动作、使用最终数据训练。频繁复核/回退应算作可靠性表现，不能删掉相关路径。真实人工介入的效果须有服务响应证据。

默认增长路线的晋级筛选，必须在实验前确定：

- 中位实际 CAGR 至少改善 0.10 个百分点/年，探索性多候选调整区间下界大于 0。
- P10 增长不能降低超过 0.10 个百分点/年，P90 MDD 不能增加超过 1 个百分点，按区间而非仅点估计判断。
- 至少 4/5 外层折方向一致，费用翻倍到 0.5% 后仍有增长优势。
- 复核频率、容忍度越界及计算失败符合预声明服务要求，并验证目标期限的客户适配。
- 保存参数/种子稳定性、训练/推理成本、动作解释以及同等表现的最简单策略。

改善增长却恶化风险时，报告取舍并进一步研究，不能宣称普遍胜出。风险降低型模型可事前反向声明：显著降低 P90 MDD，同时限制 CAGR 损失。未证明改进时保留简单参照，但不等于证明策略等效。`promotion_screen.csv` 只是探索性增长路线筛选，不是部署批准。

## 冻结与一次性最终评价

开发时不要运行真实最终评价。团队完成模型选择后，从项目根目录执行：

```bash
.venv/bin/python benchmark/run.py freeze --policy cost_aware \
  --development-run benchmark/outputs/development_consolidated \
  --bundle benchmark/frozen_policy.json
.venv/bin/python benchmark/run.py final --bundle benchmark/frozen_policy.json \
  --out benchmark/outputs/final --acknowledge-final
```

`cost_aware` 只是命令示例，不表示推荐采用。freeze 检查开发运行与当前代码、配置、数据一致，在全部 120 条开发情景上执行声明过的内层选择和重拟合，保存候选、参照、参数、环境/hash、冻结后的客户分配及最终情景 IDs。文件只能新建；这一阶段不评价最终数据。

final 验证 bundle 完整性、代码/环境和开发数据，然后在读取任何最终收益前创建 `benchmark/FINAL_EVALUATION_LOCK.json` 独占锁。按预声明期限和成本生成最终结果；即使换输出目录，也拒绝第二次运行。客户分配只评价，不根据最终结果重新推荐。

创建锁后若崩溃，锁仍视为已使用；须由独立保管者确认暴露了哪些信息并记录恢复理由，不能为换模型而删锁。可以从保存结果重新生成报告，这不重新读取市场 CSV。

该机制预防误操作，不对抗人为改代码或复制项目。更可信的做法是由另一位成员保管最终数据、签署冻结方案并执行。目录整合时尚未运行真实freeze/final；2026-10-17提交版本已按本协议执行一次，见本文件末节。自动测试始终只在生成数据上验证最终流程。

最终评价后应报告全部声明过的指标，不再调参。失败就报告失败；修改后的模型需要新的独立数据。60 条最终情景不能认证罕见风险、真实执行或实盘效果。


B/C扩展同样遵守冻结顺序：只从源码、有效配置和开发分区hash匹配的完整开发运行冻结。B/C被选中时以实际策略ID重算均衡客户映射，保守/成长仍用相应A产品；标签保持OOF诊断，不能标成固定策略覆盖。B比较列表保留整族动作/信号对照。C仅有H30筛选的配置拒绝冻结C；只有完成全部预声明期限后才可进入真实最终流程。当前两轮B/C均未建立晋级证据，本轮不创建真实冻结包或最终锁。

## 面向提交的最后一轮开发

`configs/submission.json`锁定八条执行规则（含原A）与一个内层选择程序，详见策略计划和接口。仍用原外层5/内层3整情景划分，先确定原A参数，再选择执行规则；没有合格规则则保留A且记录失败。仅选择器S8作为新提交候选，其余挑战者提供归因证据，不能看过本批外层结果后另挑固定规则提交。

S8采用条件在运行前固定：相对A通过原增长或风险路线，且相对原Balanced年度通过增长路线，或相对原Balanced年度及同锚年度同时通过风险路线；全部五期限的产品风险次序还须有效。原区间、4/5折、双倍费用、内层可行性和复核限制不变；任一整体条件不满足则提交候选保留校准A。客户风险家族大小固定440，主流动性目标比例0.4，0.2/0.3只敏感性，不以推荐人数最大化选阈值。

费用日程追加全部五期限的0.5%核验，原H30费用敏感性完整保留。开发批次仅一次；代码缺陷可修正并以新run/hash完整复算，必须保留失败记录、说明修复，不得借修复新增金融搜索。完成开发核验后停止调参、固定唯一程序和客户规则，再冻结并一次性最终评价；最终结果只评价、不调整。代码ZIP及复现说明属于本轮交付，报告/论文继续暂停。
